# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

KickCut for Android: the Android port of the KickCut desktop app (`../KickCut`, Tauri + Rust; macOS sibling `../KickCut-mac`). Downloads a Kick VOD, or a time range of it, as an editor-friendly MP4.

## Commands

Needs Node 22, JDK 17, Android SDK. The app has a native module, so **Expo Go does not work** — dev client only. `android/` is generated by prebuild (gitignored); never hand-edit it — native config goes in `app.json` or `plugins/`.

```bash
npm install
npx expo prebuild -p android          # regenerate android/ (after app.json / plugin / native-dep changes)
npx expo run:android                  # build + install dev client
npm run typecheck                     # tsc --noEmit
npm run test:engine                   # Kotlin engine JUnit suite (needs android/ from prebuild)
cd android && ./gradlew :kickcut-engine:testDebugUnitTest --tests '*MuxTest'   # single test class
npx expo install <pkg>                # add deps (SDK-compatible versions), not npm install <pkg>
```

There is no lint script and no EAS config — ignore the template advice in `AGENTS.md` about `expo lint` / `eas build`.

CI (`.github/workflows/ci.yml`) runs: gitleaks over full history → typecheck → prebuild → engine tests → `assembleRelease -PreactNativeArchitectures=arm64-v8a` → `scripts/privacy-gate.sh` on the release APK. Run the gate locally the same way (needs `ANDROID_HOME`).

Expo SDK 57 / RN 0.86 / React 19.2 — newer than most training data. Check versioned docs (`https://docs.expo.dev/versions/v57.0.0/`) before using Expo APIs from memory.

## Architecture

**Mirror the desktop, file for file.** The layout deliberately copies the desktop's flat `src/{App.tsx, panes/, lib/, i18n/}` so a desktop change maps to the same file name here. It does *not* follow the workspace's Clean-Architecture playbook, and there is no router: `src/App.tsx` switches four panes with one `useState` and keeps them all mounted. Don't introduce expo-router or feature folders.

- **`src/lib/api.ts`** — same function names and signatures as the desktop's `api.ts`, with the Kotlin native module standing where Tauri's `invoke` stood. Screens above it are the desktop's screens.
- **`src/lib/kickApi.ts`** — `kick.com/api/*` metadata via React Native `fetch` (OkHttp passes Kick's Cloudflare rule, unlike the desktop's Rust client, so this file is the desktop's webview code unchanged). Uses `Cache-Control: no-cache` because Kick marks responses cacheable for 4h.
- **`modules/kickcut-engine/`** — local Expo module, Kotlin port of the desktop's Rust (`hls.rs`→`Hls.kt`, `download.rs`→`Engine.kt`, `mux.rs`→`Mux.kt`, `rate.rs`→`RateLimiter.kt`). All `stream.kick.com` traffic (playlists, segments) goes through here. `DownloadService.kt` is a foreground service (dataSync) so jobs survive screen-off; Android 15's 6h/day limit pauses the job rather than failing it. Segment files on disk are the resume state.
- **Engine tests are the desktop's Rust tests one for one**, including the real playlist fixture `src/test/resources/kick-vod-1080p60.m3u8`. Change the Kotlin, the tests, and (if it's a behaviour fix) the desktop together.
- **ffmpeg** is bundled via ffmpeg-kit (Android won't exec a downloaded binary). The AAR hash is pinned in `scripts/ffmpeg-kit.sha256`. Mux arguments must match the desktop's `mux.rs` exactly (only the `-progress` target differs) — `MuxTest` pins them; dropping a flag silently breaks editor playback.
- Android's ICU regex rejects `(?U)`, and JVM unit tests will not catch it — test regex changes on a device/emulator.
- UI: Tailwind v4 via **uniwind** (`metro.config.js`, entry `src/global.css`, generated `src/uniwind-types.d.ts`). i18n: `src/i18n/{en,de,tr}.ts` — keep keys in sync. Job records persist in `expo-sqlite` (`src/lib/storage.ts`).
- `plugins/withReleaseSigning.js` signs release builds from `KICKCUT_RELEASE_*` Gradle properties in `~/.gradle/gradle.properties`; without them (CI) release stays debug-signed. Never put key material in the repo.

## Privacy constraints (enforced by `scripts/privacy-gate.sh`)

The README's privacy claims are checked against the built APK; a change that breaks any of these fails CI:

- Permissions exactly: `INTERNET`, `FOREGROUND_SERVICE`, `FOREGROUND_SERVICE_DATA_SYNC`, `POST_NOTIFICATIONS` (+ the dynamic-receiver one). No storage permission — the user picks the output folder via SAF. Unwanted permissions pulled in by deps go in `app.json` `blockedPermissions`.
- `allowBackup=false`, no cleartext traffic.
- No analytics / crash-reporting / ads SDKs, and no `expo-updates`.
- Source may only name `kick.com`, `stream.kick.com`, `images.kick.com` as URLs (scans `src/` and the engine's `src/main`). If you add a host, the README host table and the gate must change with it.
